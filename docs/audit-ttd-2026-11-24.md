# Audit alat "Tanda tangani PDF" — pratinjau terbalik 90 derajat

Tanggal: 2026-11-24
Alat: **Tanda tangani PDF** (`sign`)
Harness: `tools/audit-sign.mjs` (59 pemeriksaan, 0 gagal)

## 1. Bug yang dilaporkan

> "Fitur tanda tangani ada bug saat memuat dokumen pdf di preview
> dokumennya terbalik 90 derajat."

## 2. Akar masalah

Pratinjau dan PDF akhir memakai **dua sistem koordinat yang berbeda**:

| | Ruang koordinat | Ditentukan oleh |
| --- | --- | --- |
| **Pratinjau** | halaman **yang terlihat** (sudah memperhitungkan `/Rotate`) | `pdf.js` — `page.getViewport()` |
| **PDF akhir** | **ruang pengguna** (mentah, tanpa rotasi) | `pdf-lib` — `page.drawImage()` |

Untuk halaman biasa (`/Rotate 0`) keduanya sama, jadi bug-nya tidak terlihat.
Untuk halaman berotasi — sangat umum pada hasil pindai — keduanya **berbeda
murni**, sehingga:

1. tanda tangan diletakkan di koordinat yang **salah** di PDF akhir;
2. gambar tanda tangan **ikut berputar** bersama halaman, padahal di
   pratinjau ia tegak.

Contoh terukur (A4 210 × 297 mm, posisi diminta `x = 30 mm, y = 20 mm`):

| Fixture | Pratinjau | PDF akhir (sebelum perbaikan) | Selisih |
| --- | --- | --- | --- |
| `/Rotate 0` | x 34,4 · y 25,0 mm | x 34,4 · y 25,0 mm | ✓ |
| `/Rotate 90` | x 30 · y 20 mm | x 24,9 · **y 153,3** mm | **133 mm** |
| `/Rotate 180` | x 30 · y 20 mm | **x 153,1** · **y 264,8** mm | **123 / 245 mm** |
| `/Rotate 270` | x 30 · y 20 mm | **x 264,8** · y 34,6 mm | **235 mm** |

Jadi tanda tangan bisa berakhir **di sisi yang berlawanan** dari kertas —
itulah yang terlihat sebagai "dokumennya terbalik 90 derajat".

Temuan audit lain di area yang sama:

| Temuan | Dampak |
| --- | --- |
| **Tidak ada jepit (clamp)** — `x = 400 mm` diterima begitu saja | tanda tangan keluar dari kertas (batas atas kolom 400 mm) |
| Pratinjau menampilkan posisi mentahan, PDF akhir menjepit sendiri (atau sebaliknya) | angka di layar ≠ isi berkas |
| Halaman multi-ukuran (A4 + A5 + landscape) memakai ukuran halaman acuan | tanda tangan bisa keluar dari halaman A5 |
| Tidak ada cara menggeser posisi tanda tangan di pratinjau | posisi hanya bisa diketik (lambat di ponsel) |

## 3. Perbaikan

### 3.1 Penempatan sadar-rotasi (`tool-smart.js`)

`kotakTerlihat(p)` menghitung kotak halaman **yang terlihat** — sama seperti
`page.view` pada pdf.js — dari `CropBox ∩ MediaBox` plus `/Rotate`:

```js
const media = p.getMediaBox();
const crop  = p.getCropBox();
const x0 = Math.max(media.x, crop.x);
const y0 = Math.max(media.y, crop.y);
const x1 = Math.min(media.x + media.width,  crop.x + crop.width);
const y1 = Math.min(media.y + media.height, crop.y + crop.height);
const rot = ((Math.round(p.getRotation().angle / 90) * 90) % 360 + 360) % 360;
```

Lalu `gambarTanda()` menaruh gambar memakai koordinat **terlihat** `(vx, vy)`
(dari kiri / dari bawah) dan memutar image agar tetap tegak:

| `/Rotate` | Letak gambar di ruang pengguna | Rotasi image |
| --- | --- | --- |
| 0° | `x = x0 + vx`, `y = y0 + vy` | — |
| 90° | `x = x1 - vy`, `y = y0 + vx` | 90° |
| 180° | `x = x1 - vx`, `y = y1 - vy` | 180° |
| 270° | `x = x0 + vy`, `y = y1 - vx` | 270° |

Penurunan rumus ini memakai transform `PageViewport` pdf.js:

```
/Rotate 0   : canvas = (ux,  H - uy)
/Rotate 90  : canvas = (uy,  ux)          → lebar halaman = tinggi media
/Rotate 180 : canvas = (W-ux, uy)
/Rotate 270 : canvas = (H-uy, W-ux)
```

### 3.2 Jepit posisi & ukuran (`tool-smart.js` + `tool-ui.js`)

Batas = **halaman terkecil di antara halaman tujuan** (dihitung dengan
`batasTujuan()` di backend dan `hitungBatas()` di pratinjau — keduanya
memakai sumber ukuran yang sama). Posisi **dan** lebar dijepit di dalam
batas itu, rasio gambar tetap terjaga:

```
w = min(w, batasW)          h = w * (h / w)
h > batasH  →  h = batasH, w = h / rasio
x = clamp(x, 0, batasW - w)  y = clamp(y, 0, batasH - h)
```

Pratinjau menuliskan nilai yang sudah dijepit balik ke kolom X / Y / Lebar
dan memberi tahu: *"Posisi disesuaikan agar tetap di dalam halaman."*

## 4. Tambahan: posisi tanda tangan bisa digeser dengan jari

Selain memperbaiki rotasi, posisi tanda tangan sekarang bisa **digeser
langsung di pratinjau** — dengan jari, tetikus, atau pena.

### Cara kerja

Pratinjau dibungkus panggung `.sign-stage` (`position:relative`). Di atas
kanvas halaman diletakkan kotak `#signDrag` — persis di atas kotak tanda
tangan:

```html
<div class="sign-stage" id="signStage">
  <canvas id="signPreview" class="sign-preview-canvas" width="320" height="452"></canvas>
  <div id="signDrag" class="sign-drag" role="button" tabindex="0" hidden
       aria-label="Kotak tanda tangan — tekan dan geser untuk memindahkan posisi"
       aria-describedby="signPreviewHint"
       aria-keyshortcuts="ArrowUp ArrowDown ArrowLeft ArrowRight"></div>
</div>
```

Posisi kotak itu memakai **persentase terhadap halaman**, jadi tetap presisi
apa pun ukuran layarnya:

| Sisi | Rumus |
| --- | --- |
| kiri | `xMm / pageWmm * 100%` |
| atas | `(pageHmm - yMm - hMm) / pageHmm * 100%` |
| lebar | `wMm / pageWmm * 100%` |
| tinggi | `hMm / pageHmm * 100%` |

Hasil audit: selisih kotak pegangan vs kotak tanda tangan di pratinjau
= **0,0 px** (dx/dy/dw), baik di layar 1280 px maupun 375 px.

### Pointer Events (jari / tetikus / pena)

```js
drag.addEventListener("pointerdown", (e) => {
  const p = titikMm(e);                 /* CSS px -> mm, Y dari bawah */
  seret = { id: e.pointerId, dx: p.x - geo.xMm, dy: p.y - geo.yMm };
  drag.setPointerCapture(e.pointerId);  /* drag tetap jalan di luar kanvas */
  pindahkan(p.x - seret.dx, p.y - seret.dy);
});
```

- `setPointerCapture` → drag tidak terputus saat jari keluar dari kanvas;
- `touch-action:none` pada `.sign-drag` → halaman tidak ikut ter-scroll saat
  digeser dengan jari;
- **selisih jepitan** (`dx`/`dy`) → tanda tangan tidak melompat ke titik
  sentuh, melainkan mengikuti titik sentuh secara relatif;
- `pointerup` / `pointercancel` / `lostpointercapture` semuanya menutup drag
  dengan benar.

### Tetap cepat: tanpa render ulang PDF

Render ulang halaman PDF membutuhkan **9–123 ms**. Kalau tiap gerakan jari
memanggilnya, pratinjau akan tersendat. Karena itu halaman yang sudah
dirender disalin ke kanvas `snap`, dan setiap gerakan hanya menggambar ulang
**satu frame**:

```js
const gambarTanda = () => {
  pctx.clearRect(0, 0, preview.width, preview.height);
  pctx.drawImage(snap, 0, 0);                              /* halaman */
  pctx.drawImage(sigImg, geo.xPx, geo.yPx, geo.wPx, geo.hPx); /* tanda tangan */
};
```

Perubahan posisi **tidak** memanggil `onOptsChange`, jadi tidak memicu render
ulang PDF sama sekali.

### Bukti end-to-end: posisi drag benar-benar masuk PDF akhir

Pengujian paling penting: bukan hanya "pratinjau bergerak", tapi **PDF
akhir memakai posisi yang sama**. Harness menggeser tanda tangan dengan
jari, lalu membuat PDF dan mengukur kotak tintanya:

```
✓ Posisi hasil drag benar-benar BERPINDAH dari posisi awal — Δx=31.1 Δy=-18.6 mm
✓ Tinta tanda tangan di pratinjau ikut bergeser — pratinjau Δx=30.8 mm
✓ PDF hasil dibuat dari posisi hasil drag
✓ Tanda tangan hasil drag ada di PDF akhir
✓ POSISI HASIL DRAG SAMA DENGAN PDF AKHIR — kafka x=65.4 y=6.3 | pratinjau x=65.0 y=5.9 | Δ=0.5/0.4 mm
```

### Aksesibilitas

| Aspek | Implementasi |
| --- | --- |
| Peran | `role="button"` + `tabindex="0"` |
| Nama | `aria-label` ("Kotak tanda tangan — tekan dan geser…") |

| Pintasan | `aria-keyshortcuts="ArrowUp ArrowDown ArrowLeft ArrowRight"` |
| Gerak tanpa tetikus | panah kiri/kanan = 1 mm, panah atas/bawah = 1 mm, `Shift` = 5 mm |
